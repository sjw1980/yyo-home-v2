# 시트 시뮬레이터 UI — Cabin HMI 디자인 결정 기록

`src/components/SeatDiagram.tsx` · `src/components/SeatSimulator.tsx` 에 적용된
**Cabin HMI 스타일의 선택 근거**를 남기는 문서입니다.

비교용으로 만든 독립 HTML 목업 6종과 스크린샷(PNG)은 **디자인 확정 후 삭제**되었고, 이 기록만 남아 있습니다.
(목업은 빌드에 포함되지 않는 정적 파일이었고, 외부 JS 의존성 없이 인라인 CSS + 인라인 SVG로만 만들어졌습니다.)

> **적용 결과** — 6종 중 **B(릴렉스 시퀀스)** 가 앱에 이식되었습니다.
> `src/index.css`(Rajdhani · Barlow Condensed 폰트 토큰) ·
> `SeatDiagram.tsx`(라인아트 시트 + 릴렉스 타깃 고스트 포즈) ·
> `SeatSimulator.tsx`(스테이터스 바 · 3열 그리드 · 축 코리오그래피 · 진행률 링 · 시퀀스 로그 · 컨트롤별 방향 버튼)
> 세 파일이 4B 팔레트(`#0a0d0f` · `#f0a53c` · `#5fd6a4`)로 동작합니다.

## 정보 구조의 근거 (`src/seatConfig.ts`)

- 축 코드: `SLD`(슬라이드 0–300 mm) · `RCL`(리클라이너 0–60°) · `HGT`(하이트 0–100 mm) ·
  `TLT`(틸트 0–15°) · `LEG`(레그레스트 0–45°) · `CSH`(쿠션 0–60 mm) · `BLS`(볼스터 0–40 mm) ·
  `LMB`(럼버 전후 0–50 mm) · `LMH`(럼버 상하 0–50 mm) · `RLX`(릴렉스 0–100 %)
- 조작 모드 8종 (`MODE_ORDER` = 화면 상단 → 하단 = `C1` → `C8`)
  **C1 슬라이드 · C2 하이트 | C3 리클라이너 · C4 럼버 · C5 볼스터 | C6 쿠션 · C7 틸트 · C8 레그레스트**
  - 정렬 근거: ① 흔한 기능 상위(시트 전체 이동 · 등받이 → 앞) ② 오래된 기술 상위(군 안에서 오래된 축부터)
    ③ 물리적으로 비슷한 기능 근접(① 시트 전체 이동 ② 등받이 ③ 방석 전방 의 3개 군)
  - 표시 코드는 `M` 이 아니라 **Control 의 `C`** — `modeCode()` 가 배열 인덱스+1 을 반환한다.
    `MODE_CONFIG[].status`(DPSS 0x15A 신호값) 는 프로토콜 값이라 표시 코드와 분리해 고정.
  - **릴렉스는 모드 트랙에 넣지 않고** `RELAX_PRESET_KEY` 로 분리한 독립 프리셋 레이어로 다루므로
    코드 번호를 표시하지 않는다
- 릴렉스 목표값: `RELAX_ON_TARGETS` — RCL 60° / TLT 15° / LEG 45° / CSH 60 mm, SLD·HGT 중앙값 (6축)
- 소프트 리밋: `AXIS_CONFIG[].softMin/softMax` (예: RCL 5–55°, HGT 10–90 mm)

## 이식 이후에 확정된 디자인 결정

초기 목업(4B)에는 없었지만 실차 관례에 맞춰 앱에서 확정한 사항입니다.

1. **볼스터는 좌판이 아니라 등받이 좌우(엉덩이~어깨)** — 자동차 시트의 볼스터는 앉은 몸을 좌우에서 잡아주므로,
   등받이 앞면 **엉덩이(P1 피벗)에서 어깨까지** 뻗는 롱 사이드 윙으로 렌더링합니다.
   열림(0 mm)에서는 윙이 등판 면에 납작하게 붙고,
   조임(40 mm)에서는 윙이 등받이 전체 길이에 걸쳐 앞으로 나와 **럼버 패드를 안쪽에 품습니다**.
   밑단은 쿠션 뒤쪽에 겹쳐 자연스럽게 사라지며, 윙은 등받이 회전 그룹 안에 있어 리클라이너와 함께 눕습니다.
   먼 쪽 볼스터는 절선(점선)으로 그려 좌우 한 쌍임을 표시하고, 활성 축일 때만 감김 방향 쉐브론을 띄웁니다.
   릴렉스 고스트도 같은 형상으로 겹쳐 표시됩니다.
2. **쿠션 익스텐션은 좌우 조작** — ◀ = 신장 / ▶ = 수축. 도해에서 FWD가 좌측이고 익스텐션 패널이
   전방(좌측)으로 뻗어나가므로 화면 방향과 버튼 방향을 일치시켰습니다. (`LEFT_INCREASE_AXES`)
3. **레그레스트는 상하 조작** — ▲ = 올림(전개) / ▼ = 내림(폴딩). 각도 축이라 화면 위아래와 조작 방향이
   같은 상하가 자연스럽습니다(초기 안의 좌우 조작에서 변경).
4. **조작 방향은 화면의 움직임과 일치** — 값이 커지면 도해에서 **좌측(FWD)**으로 움직이는 축
   (볼스터 조임 · 쿠션 신장 · 럼버 돌출)은 `◀ = 증가`, 나머지(슬라이드 · 리클라이너)는 `◀ = 감소`로 통일했습니다.
   특히 **럼버 전후**는 초기 안이 `▶ = 돌출`이라 패드가 좌측으로 나가는데 우측 키를 누르는 것처럼 보였습니다
   (`SeatDiagram` 의 `cx = PIVOT_X + 5 - lumbarPush`). `LEFT_INCREASE_AXES` 에 `lumber` 를 넣어 바로잡았습니다.
5. **릴렉스 고스트는 이동 중에만** — 타깃 포즈(민트 점선)는 릴렉스 On으로 축이 움직이는 동안만 겹쳐 그리고,
   수동 조작 중에는 현재 포즈만 표시합니다.
6. **조작 버튼은 컨트롤 안에 — 공용 방향 로커는 폐기했다** — 한때 좌측 하단에 4키 공용 로커를 뒀다
   (모드와 무관하게 키 자리·크기·라벨을 고정하고 미매핑 방향은 어둠으로만 구분하는 방식). 그러나
   로커는 "방금 고른 모드의 축"이라는 문맥 없이 동떨어져 있고, 8개 컨트롤 중 **지금 무엇을 조작하는지
   로커만 봐서는 알 수 없다**는 점이 결정적이었습니다. 원형 아크 다이얼 · 일체형 십자 + 3D 틸트 ·
   모션 업그레이드 · 그 조합 4안을 인터랙티브 도안으로 만들어 비교했지만 전부 기각, 로커를 없애고
   **각 컨트롤(C1~C8)이 자기 방향 버튼을 자기 줄에 갖는** 구조로 바꿨습니다.
   - 버튼은 `MODE_SPEC_LABELS` 가 `null` 이 아닌 방향만 만든다 → 슬라이드·하이트·리클라이너·볼스터·
     쿠션·틸트·레그레스트는 2개, **럼버만 4개**(`grid-cols-4`). 쓰지 않는 방향을 어둡게 상주시키지 않는다.
   - 라벨은 주어(모드명)를 버린 목적어만 — `슬라이드 전진 → 전진`, `볼스터 조임 → 조임`,
     `럼버 상단 → 상단`. 볼스터처럼 방향어가 어색한 축은 원문이 그대로 목적어가 된다. 전체 문구는
     `title`("C4 · 럼버 전진") 과 `aria-label` 에 남긴다.
   - 줄 헤더(코드 · 이름 · 값 · 3px 게이지) = 컨트롤 선택, 아래 버튼 스트립 = 조작. 다른 컨트롤의
     버튼을 누르면 **그 컨트롤로 전환된 뒤** 조작된다 — `handlePress(dir, modeKey)` 가 `selectMode`
     를 먼저 부르고 축을 찾는다. 누르는 동안 연속 조작(`pointerdown → pointerup/leave`) 과
     `aria-pressed` 노출은 그대로다.
   - 치수: 버튼 24px · 라벨 9.5px · 쉐브론 12px. 한 줄이 약 73px, 8줄이 좌측 컬럼을 채운다
     (로커가 쓰던 180px 자리에 버튼 스트립 8×32px 가 들어와 콘솔 전체 높이는 오히려 줄었다).
   - 컬럼 끝에 `버튼을 누르는 동안 연속 조작 · 방향키는 선택된 컨트롤` 한 줄 — 예전 로커 헤더가
     하던 "홀드 = 연속"과 "방향키는 선택 모드용" 이라는 규칙을 이어받는다.
7. **릴렉스는 모드와 동급이 아니다 (3상태 프리셋 레이어)** — 릴렉스를 9번째 모드로 두면
   "모드 = 축 하나를 조작하는 것"이라는 나머지 8개 모드의 정의와 충돌하고,
   ON 이 0/1 플래그라 시퀀스 도중에 다른 모드로 넘어가면 반쯤 눕혀진 채로 ON 으로 표시됩니다.
   그래서 `MODE_ORDER` 에서 제외하고 **우측 컬럼(Pose Slots 아래)** 의 Relax Preset 패널로 분리했으며(코드 번호 없음), 상태는
   `OFF / 부분 적용(PARTIAL) / ON` 3상태 + 이동 방향(`APPLYING`·`RESTORING`)으로 관리합니다.
   - 100% 도달 전에 모드 전환이나 버튼 조작이 들어오면 전 축을 현재 위치에서 세우고
     **PARTIAL**(ON 도 OFF 도 아님)로 멈춥니다 — 스냅샷은 그대로 유지.
   - **OFF** 는 스냅샷 복귀, **ON(RESUME)** 은 스냅샷을 건드리지 않고 100% 까지 재개.
   - 단축키 `R` = 토글. AUTO DEMO 는 4사이클마다 모드 전환 대신 릴렉스 On→Off 를 시연합니다.
8. **RLX(적용률) 는 모터가 아니라 파생 신호** — `relaxation_return` 을 0→100 % 로 램프하면(20 %/s)
   Preset Progress 가 실제 이동과 어긋난다. 이동 거리가 짧아 0.24 s 에 끝나도 게이지는 5 s 까지 계속
   오르고, 반대로 긴 이동은 축이 아직 움직이는데 100% 가 먼저 찬다.
   그래서 `relaxApplyRatio()` 가 **OFF 포즈(스냅샷)=0 → `RELAX_ON_TARGETS`=100** 을
   **축별 이동 시간 `|거리|/속도` 의 최대값(=가장 오래 걸리는 축)** 으로 삼는다.
   `engineTick` 이 매 틱 `pos/tgt.relaxation_return` 을 이 값으로 채운다.
   - ⚠ 진행률 **최소값(min)** 집계는 방향마다 다른 축을 붙잡는다. On 은 0에서 시작해 늦게 도착하는
     축(리클라이너 3.0 s)이 최소라 맞지만, Off 는 1에서 감소해 **빨리** 도착하는 축(쿠션 2.0 s)이
     최소가 되어 시퀀스가 1 s 남았는데도 게이지가 먼저 0% 가 된다. 이동 시간 최대값으로 바꾸면
     On/Off 모두 전 축 도착 시점에 정확히 100%/0% 이고, 화면의 ETA 와도 `On: ring = 1-η/T`,
     `Off: ring = η/T` 로 일치한다.
   - 검증(30 ms 틱): On = 3.00 s / Off = 3.00 s 에 각각 100.0%·0.0% (도착 동기화 true, 단조 증가/감소),
     1.02 s 중단 = 34% 에서 정지 → 재개 1.98 s 후 100% , Off 1.02 s 중단 = 66% → 재복귀 1.98 s 후 0% .
9. **포즈 슬롯 2개 — 누르는 강도로 저장/호출을 나눠 쓴다** — 릴렉스가 "정해진 릴렉션 포즈" 라면,
   슬롯은 **사용자가 지금 이 자리에서 만든 자세** 를 담는 빈 그릇이다 (`POSE_AXES` = RLX 를 제외한 구동 9축).
   - 위치는 **우측 컬럼, Preset Progress 링 아래 · Relax Preset 위**. 좌측은 조작(컨트롤 리스트 · 현재 제어 표시),
     중앙은 연출(시트 도해·코리오그래피), 우측은 **프리셋 컬럼**(진행률 링 → 포즈 슬롯 → 릴렉스 프리셋)로
     역할을 나눴습니다. 저장/호출은 "결과를 보고 남기는" 조작이라 우측이 제자리이고, 좌측이 비고 우측이
     붐비던 밀도 불균형도 릴렉스 패널을 우측으로 넘겨 함께 잡았습니다.
   - 카드 한 장에 **탭 = 호출** / **0.6초 누름 = 저장**(차오르는 바) / **호버 = 고스트 미리보기** / **✕ = 비우기**.
     저장 버튼도, 덮어쓰기 확인창도 두지 않았다 — 확인창이 오히려 조작을 끊는다는 판단.
   - 카드는 값 목록 대신 **포즈 지문**(6축 세로 막대 = 저장값, 호버 때만 나타나는 흰 눈금 = 현재 위치) 을 보여준다.
     숫자를 읽지 않고도 "이 슬롯은 지금보다 등받이가 훨씬 젖혀져 있다" 가 보인다.
     300px 컬럼이라 값 라인은 정수 표기(`RCL 53 · LEG 40 · CSH 30 · TLT 8 · SLD 210 · HGT 50`).
   - **슬롯은 스냅샷이지 시트와의 실시간 바인딩이 아니다** — 시트와 연결된 상태로 보는 구간은
     **호출로 실제로 이동 중일 때** 뿐이다. 전 축이 도착하는 순간 `engineTick` 이 `slotTravelRef` 를
     비우면서 카드의 ETA·진행선이 사라지고 조용한 `저장됨` 상태로 돌아간다(도착은 민트 플래시 1회 +
     `SLOT P1 ARRIVED · POSE REACHED · LINK RELEASED` 로그로만 알린다). 이후 시트를 직접 움직여도
     ETA 가 되살아나지 않고, 수동 조작·릴렉스·리셋은 이동 중이던 연결을 즉시 끊는다.
   - 호출 진행률은 릴렉스 적용률과 같은 **시간 기준** `1 - η/T` — 전 축이 도착하는 순간에 정확히 100% .
     (검증: 2.25 s 호출 → 2.25 s 에 100% , 마지막 100% 미만 틱 2.22 s , 단조 증가 · drift 0 동시 도달)
   - 슬롯 호출은 **수동 포즈 명령**: 달리던 릴렉스 시퀀스를 중단시키고 ON 이었다면 부분 적용으로 강등한다.
     단 슬롯에 릴렉션 포즈를 그대로 새겨둔 경우(릴렉스 ON 상태에서 저장)에는 ON 을 유지한다.
   - `localStorage`(`yyo.seat.pose-slots.v1`) 영속. 복원할 때 `normalizePose()` 가 하드 리밋으로 클램프하고
     알 수 없는 축·손상 데이터는 통째로 버린다. 키보드 `1`·`2` = 호출, `Shift+1`·`Shift+2` = 저장.
10. **현재 제어 표시는 시트 도해 좌상단 HUD** — 모드 카드 + 4축 텔레메트리는 "지금 무엇이 움직이는가"
    이다. 컬럼에 두면 좌측 하나를 통째로 소모하고 화면 세로도 늘린다. 시트 도해는 **좌상단이 항상 비어
    있으니** 그 자리에 오버레이 HUD(214px, `bg-[#0a0d0f]/85` + backdrop-blur)로 얹었다 — 세로 공간을
    1px 도 쓰지 않는다.
    - 값은 축 코드(`RCL · LEG · CSH · TLT`) + 가능한 작은 글자로 줄여 4타일을 2×2 에 담았다.
    - **앰버 테두리 타일 = 지금 조작하는 축**(`lrAxis` + `udAxis`). HUD 하단 `조작 · LMB · LMB-H`
      라인은 타일에 없는 축(럼버·헤드레스트)을 조작 중일 때 유일한 단서가 된다 — 없는 축에 가짜 강조를 하지 않는다.
    - 컬럼 역할: **좌측 = 조작**(컨트롤 C1~C8 · 각 줄의 방향 버튼) / **중앙 = 연출**(도해 + Now Controlling HUD + 코리오그래피) /
      **우측 = 프리셋**(링 → 슬롯 → 릴렉스) + 로그.
11. **16:9 한 화면 예산** — 콘솔이 화면보다 길어 버튼·슬롯이 접히는 문제를 줄 단위로 잡았다.
    - 섹션 `py-20 → py-10 md:py-14`, 헤더 배지/타이틀/서브타이틀 축소(`text-5xl → text-[40px]`),
      스테이터스 바 `py-3 → py-2.5`.
    - **상태 배너 블록을 없애고 포커스 축 트래블 바 첫 줄에 합쳤다** — `SYSTEM IDLE · SELECT A MODE AND
      HOLD A DIRECTION KEY` 알약이 `RCL 등받이 30.0° TGT 60.0°` 와 한 줄(`truncate`)에 놓여
      세로 한 칸(약 46px)을 아낀다. 상태는 여전히 중앙 최하단, 코리오그래피 바로 위다.
    - 진행률 링 196 → 170 → **156**, 코리오그래피 행 간격(`mb-1.5 → mb-1`)·패딩(`py-3 → py-2.5`) 축소,
      도해 최소 높이 520 → 420, 로커 폐기(−140px) → 컨트롤 버튼 스트립(8×32px).
    - **설명 문구는 한 줄로 줄였다** — 슬롯 힌트(`호버 = 시트에 점선 미리보기`), 릴렉스 상태 힌트
      (`OFF = 스냅샷 복귀` 등 5상태 각 1줄), 콘솔 아래 `Seat Control Hint`(약 500자 → 단축키 한 줄).
      동작 의미는 패널 안의 라벨(컨트롤 버튼 라벨 · `탭=호출 · 길게=저장` · HUD `조작 · LMB`)이 이미 전한다.
    - **정렬 기준선**: 로커가 비운 자리는 컨트롤 8줄이 채운다. 3열 높이는 여전히 우측 컬럼이 결정하고,
      좌측은 C8 아래 홀드 안내 한 줄로 마무리 — 콘솔 전체 높이는 로커 시절보다 오히려 낮아졌다.
    - 합계 약 260px 절약 — 1080p(뷰포트 ~950px) 에서 컨트롤 8줄·도해 HUD 가 접히지 않는다.

## 미채택 화면에서 가져올 수 있는 위젯

- **A(조작 콘솔)** — 인벨로프 바(`min → softMin → 현재값 → softMax → max` 를 % 로 변환), HOLD 프로그레스
- **C(정비 진단)** — 결함 위치 강조: `SeatDiagram` 부품 그룹에 `id` 만 부여하면 축 단위 강조 가능.
  DTC·전류 파형·벤치 테스트는 **모의 데이터**이므로 진단 프로토콜 연동 전에는 연출 전용
- **D(인체공학)** — 마네킹 5관절 polyline(고관절·슬관절·견부·발목·두부) + 각도 호. percentile 에 따라 좌표 재계산
- **E(메모리)** — 메모리 슬롯 아이디어는 우측 상단(Preset Progress 아래) **포즈 슬롯**(결정 9번) 으로
  채택했다. 3중 고스트 오버레이 대신 호버한 슬롯 1개만 민트 점선 고스트로 겹쳐 그리고,
  레일 색상 눈금(슬라이드 메모리 마커)은 미채택
