## 정보 구조의 근거 (`src/seatConfig.ts`)

- 축 코드: `SLD`(슬라이드 0–300 mm) · `RCL`(리클라이너 0–60°) · `HGT`(하이트 0–100 mm) ·
  `TLT`(틸트 0–15°) · `LEG`(레그레스트 0–45°) · `CSH`(쿠션 0–60 mm) · `BLS`(볼스터 0–40 mm) ·
  `LMB`(럼버 전후 0–50 mm) · `LMH`(럼버 상하 0–50 mm) · `RLX`(릴렉스 0–100 %)
- 조작 모드 8종 (`MODE_ORDER` = 화면 상단 → 하단 = `C1` → `C8`)
  **C1 슬라이드 · C2 하이트 | C3 리클라이너 · C4 럼버 · C5 볼스터 | C6 쿠션 · C7 틸트 · C8 레그레스트**
  - 정렬 근거: ① 흔한 기능 상위(시트 전체 이동 · 등받이 → 앞) ② 오래된 기술 상위(군 안에서 오래된 축부터)
    ③ 물리적으로 비슷한 기능 근접(① 시트 전체 이동 ② 등받이 ③ 방석 전방 의 3개 군)
  - 표시 코드는 `M` 이 아니라 **Control 의 `C`** — `modeCode()` 가 배열 인덱스+1 을 반환한다.
    `MODE_CONFIG[].status`(DPSS 0x15A 신호값) 는 프로토콜 값이라 표시 코드와 분리해 고정.
  - **릴렉스는 모드 트랙에 넣지 않고** `RELAX_PRESET_KEY` 로 분리한 독립 프리셋 레이어로 다루므로
    코드 번호를 표시하지 않는다
- 릴렉스 목표값: `RELAX_ON_TARGETS` — RCL 60° / TLT 15° / LEG 45° / CSH 60 mm, SLD·HGT 중앙값 (6축)
- 소프트 리밋: `AXIS_CONFIG[].softMin/softMax` (예: RCL 5–55°, HGT 10–90 mm)

## 이식 이후에 확정된 디자인 결정

초기 목업(4B)에는 없었지만 실차 관례에 맞춰 앱에서 확정한 사항입니다.

1. **볼스터는 좌판이 아니라 등받이 좌우(엉덩이~어깨)** — 자동차 시트의 볼스터는 앉은 몸을 좌우에서 잡아주므로,
   등받이 앞면 **엉덩이(P1 피벗)에서 어깨까지** 뻗는 롱 사이드 윙으로 렌더링합니다.
   열림(0 mm)에서는 윙이 등판 면에 납작하게 붙고,
   조임(40 mm)에서는 윙이 등받이 전체 길이에 걸쳐 앞으로 나와 **럼버 패드를 안쪽에 품습니다**.
   밑단은 쿠션 뒤쪽에 겹쳐 자연스럽게 사라지며, 윙은 등받이 회전 그룹 안에 있어 리클라이너와 함께 눕습니다.
   먼 쪽 볼스터는 절선(점선)으로 그려 좌우 한 쌍임을 표시하고, 활성 축일 때만 감김 방향 쉐브론을 띄웁니다.
   릴렉스 고스트도 같은 형상으로 겹쳐 표시됩니다.
2. **쿠션 익스텐션은 좌우 조작** — ◀ = 신장 / ▶ = 수축. 도해에서 FWD가 좌측이고 익스텐션 패널이
   전방(좌측)으로 뻗어나가므로 화면 방향과 버튼 방향을 일치시켰습니다. (`LEFT_INCREASE_AXES`)
3. **레그레스트는 상하 조작** — ▲ = 올림(전개) / ▼ = 내림(폴딩). 각도 축이라 화면 위아래와 조작 방향이
   같은 상하가 자연스럽습니다(초기 안의 좌우 조작에서 변경).
4. **조작 방향은 화면의 움직임과 일치** — 값이 커지면 도해에서 **좌측(FWD)**으로 움직이는 축
   (볼스터 조임 · 쿠션 신장 · 럼버 돌출)은 `◀ = 증가`, 나머지(슬라이드 · 리클라이너)는 `◀ = 감소`로 통일했습니다.
   특히 **럼버 전후**는 초기 안이 `▶ = 돌출`이라 패드가 좌측으로 나가는데 우측 키를 누르는 것처럼 보였습니다
   (`SeatDiagram` 의 `cx = PIVOT_X + 5 - lumbarPush`). `LEFT_INCREASE_AXES` 에 `lumber` 를 넣어 바로잡았습니다.
5. **릴렉스 고스트는 이동 중에만** — 타깃 포즈(민트 점선)는 릴렉스 On으로 축이 움직이는 동안만 겹쳐 그리고,
   수동 조작 중에는 현재 포즈만 표시합니다.
6. **방향 로커는 설정 기반** — `MODE_SPEC_LABELS` 가 `null`인 방향은 빈 자리표시자로 채워
   모드마다 활성 키 개수가 달라집니다(럼버만 4방향, 나머지 7개 조작 모드는 2방향).
7. **릴렉스는 모드와 동급이 아니다 (3상태 프리셋 레이어)** — 릴렉스를 9번째 모드로 두면
   "모드 = 축 하나를 조작하는 것"이라는 나머지 8개 모드의 정의와 충돌하고,
   ON 이 0/1 플래그라 시퀀스 도중에 다른 모드로 넘어가면 반쯤 눕혀진 채로 ON 으로 표시됩니다.
   그래서 `MODE_ORDER` 에서 제외하고 좌측 **상단**의 Relax Preset 패널로 분리했으며(코드 번호 없음), 상태는
   `OFF / 부분 적용(PARTIAL) / ON` 3상태 + 이동 방향(`APPLYING`·`RESTORING`)으로 관리합니다.
   - 100% 도달 전에 모드 전환이나 로커 조작이 들어오면 전 축을 현재 위치에서 세우고
     **PARTIAL**(ON 도 OFF 도 아님)로 멈춥니다 — 스냅샷은 그대로 유지.
   - **OFF** 는 스냅샷 복귀, **ON(RESUME)** 은 스냅샷을 건드리지 않고 100% 까지 재개.
   - 단축키 `R` = 토글. AUTO DEMO 는 4사이클마다 모드 전환 대신 릴렉스 On→Off 를 시연합니다.
8. **RLX(적용률) 는 모터가 아니라 파생 신호** — `relaxation_return` 을 0→100 % 로 램프하면(20 %/s)
   Preset Progress 가 실제 이동과 어긋난다. 이동 거리가 짧아 0.24 s 에 끝나도 게이지는 5 s 까지 계속
   오르고, 반대로 긴 이동은 축이 아직 움직이는데 100% 가 먼저 찬다.
   그래서 `relaxApplyRatio()` 가 **OFF 포즈(스냅샷)=0 → `RELAX_ON_TARGETS`=100** 을
   **축별 이동 시간 `|거리|/속도` 의 최대값(=가장 오래 걸리는 축)** 으로 삼는다.
   `engineTick` 이 매 틱 `pos/tgt.relaxation_return` 을 이 값으로 채운다.
   - ⚠ 진행률 **최소값(min)** 집계는 방향마다 다른 축을 붙잡는다. On 은 0에서 시작해 늦게 도착하는
     축(리클라이너 3.0 s)이 최소라 맞지만, Off 는 1에서 감소해 **빨리** 도착하는 축(쿠션 2.0 s)이
     최소가 되어 시퀀스가 1 s 남았는데도 게이지가 먼저 0% 가 된다. 이동 시간 최대값으로 바꾸면
     On/Off 모두 전 축 도착 시점에 정확히 100%/0% 이고, 화면의 ETA 와도 `On: ring = 1-η/T`,
     `Off: ring = η/T` 로 일치한다.
   - 검증(30 ms 틱): On = 3.00 s / Off = 3.00 s 에 각각 100.0%·0.0% (도착 동기화 true, 단조 증가/감소),
     1.02 s 중단 = 34% 에서 정지 → 재개 1.98 s 후 100% , Off 1.02 s 중단 = 66% → 재복귀 1.98 s 후 0% .

## 미채택 화면에서 가져올 수 있는 위젯

- **A(조작 콘솔)** — 인벨로프 바(`min → softMin → 현재값 → softMax → max` 를 % 로 변환), HOLD 프로그레스
- **C(정비 진단)** — 결함 위치 강조: `SeatDiagram` 부품 그룹에 `id` 만 부여하면 축 단위 강조 가능.
  DTC·전류 파형·벤치 테스트는 **모의 데이터**이므로 진단 프로토콜 연동 전에는 연출 전용
- **D(인체공학)** — 마네킹 5관절 polyline(고관절·슬관절·견부·발목·두부) + 각도 호. percentile 에 따라 좌표 재계산
- **E(메모리)** — 등받이/헤드레스트 그룹을 `rotate()`/`translate()` 만 다르게 복제한 3중 고스트 오버레이,
  레일 색상 눈금 = 슬라이드 메모리 마커
